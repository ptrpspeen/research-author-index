# Research Author Index

Produce one researcher's report with exactly two sheets, `Scopus` and `TCI`. Answer in the user's language. Scripts live at the **plugin root**, two directories above this skill directory, not inside this skill. Run commands from that root; put all research outputs in the user's workspace. Use `python3` (Windows: `py -3`, otherwise `python`); Excel requires `openpyxl>=3.1,<4`.

## Mandatory first step: open Scopus and verify login

At the start of every research run, **before searches, collection, imports or draft checks**, visibly open [Scopus](https://www.scopus.com/) for the user. Honor an explicitly chosen browser; otherwise use connected Chrome, or Codex Browser (the in-app browser, visible) when Chrome is not connected. Reuse and show an existing Scopus tab in that browser when available. If no browser is usable, ask the user to enable one and wait.

Inspect the current UI for signed-in evidence, such as an account menu identifying the user with a sign-out action. An accessible home page, author results, institutional logo or old session note does **not** prove login. If already signed in, record the browser/tab and verification, then continue; do not force logout or another login.

If signed out or status is uncertain, open the visible Sign in flow, keep it visible, and tell the user in their language to log in there before work can start. If the login UI is unavailable or fails to open, keep the current page visible, explain the blocker and ask the user to complete login or enable a working browser; remain paused. **Pause the research workflow until the user finishes and a fresh UI check confirms login.** Do not start ThaiJO, import a CSV, infer zero results or declare Export broken while this prerequisite is pending. The user enters credentials/MFA themselves; never ask for them in chat. If login expires later, repeat this gate. Signed-in status and subscription access are separate; report any remaining access error accurately.

**Existing ThaiJO draft/status check, after the login gate:** run `python3 scripts/collect_thaijo.py --review-draft FILE --author-name "VERIFIED NAME"` (repeat `--author-name` for verified Thai/English aliases). Use its exact counts; do not write ad hoc field/name counters. Coverage comes from saved collection-state/audit, not row count alone. Report TCI-relevant fields; Scopus citations/h-index are not required fields of a TCI row. Then inspect only the reported gaps and decide readiness using the evidence rules below.

## Non-negotiable evidence

- Use Scopus through the user's verified browser session: accessibility/screenshot or documented Playwright DOM/locators and UI CSV downloads. Prefer supported download capture; follow current tool documentation, never invent methods. Do not call private Scopus endpoints, intercept network traffic, copy cookies or send its authenticated pages to an external scraper. Python processes downloaded CSV only. Other databases cannot substitute for Scopus records.
- Identify the person before collecting: full name plus affiliation/profile evidence. A matching surname, existing tab or file name is insufficient. If unresolved, ask for affiliation/ORCID/Author ID while continuing independent work. Never guess transliteration, ORCID, metrics or missing authors.
- One article per database row. Keep overlaps in both sheets. Each row needs a direct article URL. Unknown values stay blank with a reason; unknown citation counts are not zero. Incomplete authors require `authors_complete:false`, `verification_status:needs_review`.
- Q/Tier describe journals; h-index describes the Scopus author. Q needs CiteScore year, percentile, subject and source URL. Use publication-year evidence; only current-year papers may use the latest completed prior year with a note. Never transfer Q across subjects. Conference papers have no journal Q by default. Tier needs period evidence covering the article year; explicit continuous publisher “since” statements are separately labeled, never treated as certified expiry. Keep current-only Tier in its dated current fields. Do not infer historical values.
- Access failure is not zero results. Do not claim completeness without observed counts/pages/filters. Do not deliver an empty Scopus sheet unless zero is verified or the user has accepted a clearly partial report. Otherwise preserve a draft and explain the blocker. Never bypass login/CAPTCHA.

## Workflow — load only the reference for the current stage

0. Complete the mandatory visible Scopus/login step above. This is a prerequisite, not an optional recovery action.
1. Inspect only likely attached/workspace reports, reading researcher metadata first. Reuse `--previous` only for this person. If none matches, start a new report without asking for an optional old file; ask only if the user specifically requests an update to a missing report.
2. Read [collection.md](references/collection.md). Establish name variants from evidence. Search ThaiJO with Thai full name first; Scopus with surname + first name. Record actual queries, profile IDs, counts, filters, dates, pages and exclusions. Stop redundant name searches once the identity and profile coverage are established.
3. For Scopus read [scopus-export-computer-use.md](references/scopus-export-computer-use.md). Confirm AU-ID, export the whole current result set, verify modal count and CSV count. Read h-index/ORCID from the profile if accessible. Preserve the downloaded file.
4. For ThaiJO read [fast-collection.md](references/fast-collection.md): extract observed public profile links once, then collect missing pages with the browser and resolve detail links in one script call. A partial payload is not full coverage. Run `collect_thaijo.py --urls article-urls.txt --author-name "VERIFIED FULL NAME" --output thaijo-draft.json`; repeat `--author-name` for evidenced aliases. Read its exact `missing_fields`/`target_name_matches` counts; year key is `publication_year`, not `year`. For an existing draft replace `--urls` with `--review-draft thaijo-draft.json` to check offline. Name matching normalizes Unicode/whitespace but does not prove identity. Inspect unmatched/ambiguous rows; article citation/issue metadata controls year, not profile import dates or the journal's current issue.
5. Read [incremental-update.md](references/incremental-update.md) for import commands. Import complete current sets; compare counts and review only added/changed records. Never override missing-record protection without verifying the removal. An unrefreshed database remains explicitly unrefreshed. Reuse existing metric evidence only within its year/subject/certification scope.
6. Query missing journal metrics once per source/year/subject. A queue is pending work; attempt its checks before finishing, or document an observed blocker/unavailable year. For TCI read [tier-evidence.md](references/tier-evidence.md): collect About/indexing/announcements and linked documents once per journal, review exact Tier/period claims, then apply them. An undated badge fills current Tier only. Attempt historical sources even when a current badge exists. Leave unavailable metrics blank with evidence-based reasons.
7. Use [data-contract.md](references/data-contract.md) only when editing JSON/audit. Run reconciliation, ThaiJO link checks and exporter preflight per incremental-update.md. Resolve mismatches; disclose remaining evidence gaps. Export and verify sheet names, row counts and hyperlinks. Deliver Excel, source JSON and a brief coverage/limitation summary.

## Token discipline

Read summaries first; do not print whole reports, CSVs, HTML, tool catalogs or all references. Inspect only identity metadata, errors, changed records and unresolved metrics. Use UI state diffs after each meaningful action; full states/screenshots only when needed. Reuse downloaded CSV and ThaiJO metadata for validation. `incremental_update.py` already reuses valid metrics: do not repeat cache extract/apply. Start metric queues without `--changes` on a new report; use it on updates, noting unchanged missing metrics remain unresolved. Never save tokens by skipping identity, counts or evidence checks.
